Application Layer - PART 1
    * Goal: build the complete application behavior with temporary storage and prove the API,
        business logic, and job flow.
    * Deliverables:
        - working FastAPI application
        - in-memory or file-backed data storage
        - user/workspace ownership enforcement
        - CSV import endpoint
        - record listing endpoint
        - processing job trigger endpoint
        - job status endpoint
        - tests for core business behavior
        - documentation / README
    * Component Responsibilities:
        app/main.py
            - instantiate FastAPI app
            - mount routers
            - register startup/shutdown
            - expose GET /health
        app/api/routers.py
            - configure route registration
            - combine users, workspaces, records, jobs
        app/api/users.py
            - POST /users
            - create new user
            - return user id/name
        app/api/workspaces.py
            - POST /workspaces
            - create workspace and assign owner
            - verify owner payload    
        app/api/records.py
            - POST /workspaces/{workspace_id}/records/import
                - upload CSV / payload
                - parse rows
                - skip blank rows
            - assign workspace ownership
                - GET /workspaces/{workspace_id}/records
                - list workspace records only
        app/api/jobs.py
            - POST /workspaces/{workspace_id}/jobs/process
                - create/process job
                - start background work
            - GET /jobs/{job_id}
                - job status and results
        app/models/domain.py
            - define domain types:
                - User
                - Workspace
                - Record
                - Job
        app/models/schemas.py
            - request/response Pydantic models
            - schema for import payload
            - schema for job status
        app/services/user_service.py
            - business operations for users
            - create and retrieve users
        app/services/workspace_service.py
            - workspace creation
            - ownership verification
            - workspace retrieval
        app/services/record_service.py
            - import records
            - normalize record fields
            - validate record fields
            - assign tags
            - list workspace records
        app/services/job_service.py
            - create and track jobs
            - orchestrate processing
            - update status
            - expose query results
        app/storage/repository.py
            - repository interfaces:
                - UserRepository
                - WorkspaceRepository
                - RecordRepository
                - JobRepository
        app/storage/in_memory.py (Part 1)
            - implement repository interfaces with dictionaries
            - simple unique ID generation
            - state kept in process memory
            - good for fast prototypes
        app/storage/file_storage.py (optional Part 1)
            - optional local JSON file backing
            - still interface-based
            - useful for restart persistence without DB
        app/jobs/processor.py
            - record processing logic:
                - trim whitespace
                - lowercase email
                - mark invalid if email missing
                - assign tags:
                    - complete
                    - missing_email
                    - missing_company
                    - incomplete
        update records with validation and tags
        app/jobs/queue.py
            - simple queue abstraction
            - optional worker thread/process
            - can be internal to the FastAPI process
Execution Plan - PART 1
1. Scaffold project
    * create app/ and tests/ directories, pyproject.toml, .gitignore, README.md
    * install FastAPI, Uvicorn, pytest
2. Define domain model (set of classes or DS that represent the real concepts the app is working with)
    * implement app/models/domain.py - defines the core business entities/represents the app's internal data concepts
        - what the app is working with internally
    * implement app/models/schemas.py - defines API structures/used for request validation and response formatting
        - how data enters and leaves the app through the API
3. Define repository interfaces
    - a code file that defines the data access layer
        - holds the repositiory interfaces/abstractions
        - describes how the app reads and writes data
        - Repository: represents a collection of domain objects
            - HIDES STORAGE DETAILS from the rest of the app
            - services ask the repository for data, not raw DB/files
    * implement app/storage/repository.py
    * define method contracts for CRUD and queries
        - CRUD: Create, Read, Update, Delete
            - Example: create a user, read a workspace, update record after processing delete a job if needed
        - Query: request for data
        - "defining contracts": writing the function names and in/outputs without deciding how they work yet
4. Implement in-memory storage
    * implement app/storage/in_memory.py
    * use dictionaries and lists
    * ensure ownership filtering in repository methods
5. Implement services
    - a layer of code that implements business rules and orchestration
    - keeps business logic centralized, testable, and controllers/routers thin
    - validates, authorizes, orchestrates, transforms, handles errors, and keeps logic storage-agnostic
        - agnostic: not tied to a specific choice; makes code easier to test, replace, maintain
    * user_service.py
    * workspace_service.py
    * record_service.py
    * job_service.py
    * keep logic independent of storage implementation
6. Implement processing logic
    - code that takes raw imported records and applies the business rules
        to transform, validate, and classify them so they become usable data
    - turns raw CSV rows into normalized, validated domain Records and assign a tag/status
    * build app/jobs/processor.py
    * create clear tag decision tree
    * ensure records are normalized consistently
7. Implement API routes
    - API routes: the URLs your app exposes so external clients can talk to it
    - each route is one endpoint that doesn one thing
        - Example: POST/users -> create new user
    * build endpoints in app/api/*.py
    * wire services through dependency injection
    * enforce user/workspace ownership checks at API layer
    * expose GET /health
8. Add tests
    * tests/test_services.py
    * normalization unit tests
    * tag assignment tests
    * ownership business rules
    * tests/test_api.py
    * endpoint behavior
    * import and processing job flow
    * ests/test_storage.py

    * README.md

    * how to run

    - can change server state

    - used to read or fetch information

* Data flow
    HTTP request → API router
    router validates schema
    router calls service
    service enforces ownership + business rules
    service calls repository methods
    repository reads/writes storage
    job service triggers processor
    processor updates record states
    API returns structured response

Ownership Bounderies:
    * workspace always belongs to a single user
    * every record belongs to exactly one workspace
    * all record listing and job actions are scoped to workspace and owner

Separation of Concerns:
    - API only handles transport and validation
    - services handle business decisions
    - repositories handle persistence
    - jobs handle background processing
    - domain models capture business state

Job processing
    import CSV
    create job object
    process records one-by-one
    trim text fields
    lowercase email
    tag record
    mark invalid when needed
    record status updated
    job status query returns progress and result
